### 4. `CheckpointMeta.n_iters` — rendered in `RunsRail` but never populated by the list endpoint
- **Location:** backend [checkpoint.py:72](ui/backend/routes/checkpoint.py#L72) (`_list_autosave_checkpoints` sets `"n_iters": None`) and [:79-90](ui/backend/routes/checkpoint.py#L79-L90) (`list_checkpoints` preset branch omits the field) vs. frontend [RunsRail.tsx:154-155](ui/src/components/shell/rails/RunsRail.tsx#L154-L155)

- **Removal risk:** **low** — either drop the field from the list-item shape or actually compute it at list time; the current state is a guaranteed-empty UI branch.

## Duplicated logic

### 5. Constraint-satisfaction (goal + tolerance pass/fail) rule reimplemented in 4+ backend/library/FE places
- **Location:** [score_service.py:11-19](ui/backend/services/score_service.py#L11-L19) (`_raw_directional_error`) + [checkpoint_reader.py:138-144](ui/backend/services/checkpoint_reader.py#L138-L144) (`compute_envelope`) and [:188-194](ui/backend/services/checkpoint_reader.py#L188-L194) (`compute_scatter._is_feasible`) + [ui/src/lib/utils.ts:35-43](ui/src/lib/utils.ts#L35-L43) (`statusForGoal`) — vs. the library's canonical [base.py:947-986](src/spicexplorer/optimization/base.py#L947-L986) (`compute_constraint_violation_penalty_for_spec`)
- **Why it is redundant:** Confirmed at HEAD — the directional pass/fail math (`exceed: v >= target - tol`; `minimize: v <= target + tol`; `exact: |v - target| <= tol`; default `tol = 0.05 * target`) is independently coded in `score_service._raw_directional_error`, twice more inside `checkpoint_reader` (envelope feasibility and scatter `_is_feasible`), and again on the FE in `statusForGoal` ([utils.ts:31](ui/src/lib/utils.ts#L31) sets the `0.05*target` default; [:36](ui/src/lib/utils.ts#L36)/[:39](ui/src/lib/utils.ts#L39) apply `target ± tol`). None of these call the library's authoritative `compute_constraint_violation_penalty_for_spec`, which the **actual optimizer** uses ([base.py:943](src/spicexplorer/optimization/base.py#L943), [:1013](src/spicexplorer/optimization/base.py#L1013)). `compute_score` (`score_service`) is consumed **only** by `/api/score` ([routes/score.py:35](ui/backend/routes/score.py#L35)) — it is a parallel scorer, not a call into the library. Four-plus copies of one rule that must be hand-kept in lockstep across the HTTP boundary.
- **Removal risk:** **high** — spans the FE/backend boundary and the optimizer. Truly unifying would mean the FE always asking the backend for status (and the backend calling the library scorer). High blast radius — flagged for awareness, not a quick fix.

### 6. `score_service` penalty block duplicated verbatim between the per-spec loop and the curve loop
- **Location:** [score_service.py:58-63](ui/backend/services/score_service.py#L58-L63) (per-spec loop) vs [:92-97](ui/backend/services/score_service.py#L92-L97) (curve loop)
- **Why it is redundant:** Confirmed at HEAD — the `raw → (linear_p, sigmoid_p)` computation (`if raw <= 0.0: 0.0 else compute_relative_absolute_error/compute_relative_sigmoid_error(raw, 0, rang)`) is written twice: once in the per-spec loop and again verbatim inside the curve-building loop. The default-tolerance derivation `0.05 * target` is likewise repeated at [:42](ui/backend/services/score_service.py#L42) and [:84](ui/backend/services/score_service.py#L84). A single inner helper (`raw → (linear, sigmoid)`) removes the second copy.
- **Removal risk:** **low** — same module, identical math; refactor is behavior-preserving.

### 7. `goalSym` (goal → comparison glyph) reimplemented in 8 components with two divergent glyph sets

- **Why it is redundant:** Confirmed at HEAD (still unfixed) — the same `goal → symbol` mapping is re-declared in 8 places and the **glyphs disagree**: four sites emit `>` / `<` and four emit `≥` / `≤` for the identical goals, a visible inconsistency. A single shared helper in [lib/utils.ts](ui/src/lib/utils.ts) (with one canonical glyph choice) would fix both the duplication and the inconsistency. - **Removal risk:** **low** — UI-only string; extracting one helper is safe, though it forces a one-time choice of a canonical glyph set.

### 8. Spec pass/fail helper duplicated across the FE, with two inline copies that ignore tolerance
- **Location:** [HealthTab.tsx:16-18](ui/src/components/tabs/HealthTab.tsx#L16-L18) (`passesSpec`) and [ExplorerTab.tsx:33-35](ui/src/components/tabs/ExplorerTab.tsx#L33-L35) (`passesSpec`) wrap `statusForGoal` identically; [PipelineView.tsx:108-111](ui/src/components/tabs/PipelineView.tsx#L108-L111) (`specPass`) and [RightRail.tsx:40-46](ui/src/components/shell/RightRail.tsx#L40-L46) (inline) re-derive pass/fail
- **Why it is redundant:** Confirmed at HEAD — `HealthTab` and `ExplorerTab` each define an identical `passesSpec` wrapper around [lib/utils.statusForGoal](ui/src/lib/utils.ts#L21), while `PipelineView.specPass` ([:111](ui/src/components/tabs/PipelineView.tsx#L111)) and `RightRail`'s inline check ([:42-46](ui/src/components/shell/RightRail.tsx#L42-L46)) compare against the **bare target** for `exceed`/`minimize` (`v >= target` / `v <= target`), **ignoring tolerance** — so they can report a different verdict than `statusForGoal` (which applies `target ± tol`) for the same spec. [ManualSimPanel.tsx:316](ui/src/components/pvt/ManualSimPanel.tsx#L316) correctly uses `statusForGoal`. Consolidating all four to `statusForGoal` removes the dup **and** fixes the two tolerance-ignoring copies.
- **Removal risk:** **medium** — the helper-wrapper consolidation is trivial, but unifying the two inline copies onto `statusForGoal` is a **deliberate behavior change** (they would start honoring tolerance); do it consciously.

## Convoluted / over-indirect paths

### 9. `score_service.compute_score` is a parallel scorer that re-derives the optimizer's penalty instead of calling it
- **Location:** [score_service.py:22-105](ui/backend/services/score_service.py#L22-L105) (`compute_score`), consumed only by [routes/score.py:35](ui/backend/routes/score.py#L35) (`POST /api/score`); the library's authoritative path is [base.py:1009-1015](src/spicexplorer/optimization/base.py#L1009-L1015) (`compute_fitness_for_spec`) → [:947-986](src/spicexplorer/optimization/base.py#L947-L986) (`compute_constraint_violation_penalty_for_spec`)
- **Why it is unclear:** Confirmed at HEAD — the Score Shaping UI gets its penalties from `compute_score`, which rebuilds the directional-error + relative-absolute/sigmoid normalization **in the backend** rather than invoking the library's `compute_constraint_violation_penalty_for_spec` that the real optimizer uses. The two share the leaf helpers (`compute_relative_absolute_error`/`compute_relative_sigmoid_error` from [core.utils](src/spicexplorer/core/utils.py)), but the gating / short-circuit / weighting logic is independently coded, so the displayed penalty curve can silently drift from what the optimizer actually scores. This is an over-indirect path: the canonical scorer exists in the library, but the UI route reimplements it. (Closely related to item 5 — that item is the rule-level duplication; this is the module-level over-indirection.)
- **Removal risk:** **high** — re-pointing `/api/score` at the library scorer changes the displayed numbers and crosses the FE/backend contract; needs a deliberate scoring-parity pass.

## Suggested cleanup order

Ordered lowest-risk / highest-clarity-gain first; each is independent unless noted.

1. **Collapse `bottomTab`** to a static label (item 10) — removes a fake one-tab abstraction; no behavior change.
2. **Either compute or drop `CheckpointMeta.n_iters`** in the list path (item 4) — resolve the guaranteed-empty `RunsRail` branch.
3. **Extract the inner penalty helper** in `score_service.py` (item 6) — same-file, behavior-preserving dedup of the per-spec/curve loops.
4. **Extract one `goalSym` helper** into `lib/utils.ts` (item 7) — pick a canonical glyph set; removes a visible inconsistency.
5. **Delete `Nevergrad_Symbolic_Bode_Fitter` / `symbolic.py`** (item 3) — zero importers and no test; confirm it is not intended WIP first.
6. **Route the two inline FE pass/fail copies through `statusForGoal`** (item 8) — low effort, but a deliberate behavior change for `PipelineView.specPass` and `RightRail` (they would start honoring tolerance); do it consciously, then fold `HealthTab`/`ExplorerTab` `passesSpec` into the shared helper.
7. **Decide the fate of `newcas_demo_runner.py`** (item 1, medium) — dead relative to the webapp and references a non-existent route, but carries a dependent test; needs product sign-off (removal also deletes its sole copy of `_safe_float`).
8. **Retire the legacy SVG schematic route** once `SetupTab` adopts the xschem viewer (item 11, medium) — requires a UI migration first; verify symbol rendering on the PDK-equipped server at runtime before committing.
9. **Unify the score path** (items 5 + 9, high) — re-point `/api/score` and the FE status checks at the library's `compute_constraint_violation_penalty_for_spec` so the displayed penalties match what the optimizer scores; needs a scoring-parity pass across the FE/backend boundary.
10. **Decide the fate of the RL subtree** (item 2, high) — 1557 LOC dead relative to the webapp but possibly deliberate research WIP, with two dependent tests; needs product sign-off.
